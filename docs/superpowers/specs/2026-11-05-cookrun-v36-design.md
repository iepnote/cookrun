## 1. 디자인 통합 규칙

### 1-1. 크기 토큰 (CSS 변수, `:root`)

| 변수 | 값 | 용도 |
|---|---|---|
| `--sz-hand` | 10vmin | 모든 손 그림(쥔 손·잡는 손·칼 쥔 손). 크기 인자 제거 |
| `--sz-tool` | 20vmin | 숟가락·거품기·케첩통·국자 등 손에 드는 도구의 긴 축 |
| `--sz-knife` | 36vmin | 칼의 긴 축(유일한 예외, 길고 얇은 도구) |
| `--sz-food` | 30vmin | 조작 대상이 되는 음식 한 덩이(바나나, 반죽 그릇 속 내용물, 샌드위치) |
| `--sz-ing` | 16vmin | 옆 쟁반·장바구니의 재료 카드 기준 폭. 여기에 실제 비율표를 곱함 |
| `--sz-vessel` | 50vmin | 접시·그릇·팬·믹서·오븐·세면대·컵 등 담는 것의 폭 |
| `--sz-bit` | 5vmin | 밥 한 술, 요거트 한 스푼, 썬 조각, 가루 알갱이 |

비율은 손 : 도구 : 음식 : 그릇 = 1 : 2 : 3 : 5. 기존 `--plateW`(73vmin)는 `--sz-vessel`로 대체한다. 빵은 접시 폭의 60%(=`--sz-food`)로 올라간다.

### 1-3. 화면 종류 3가지와 요리별 배정

| 화면 종류 | 헬퍼 | 구성 | 동작 |
|---|---|---|---|
| 탁자형 | `sceneTable(centerHTML, trayHTML)` | 가운데 접시(`--sz-vessel`) + 오른쪽 재료 쟁반(세로) | 놓기·올리기·덮기·담기·바르기·짜기·뿌리기·주기 |
| 도마형 | `scenePov(innerHTML, hint)` (기존 `povStage`) | 기울어진 도마 + 가운데 음식 + 아래에서 올라오는 손 | 썰기·젓기·붓기·뒤집기·까기·뭉치기·달걀 깨기·꽂기 |
| 기기형 | `sceneDevice(innerHTML, hint)` | 가운데 기계(`--sz-vessel`) + 단추 | 오븐·믹서·세면대·수도꼭지·설거지 |

| 요리 | 화면 흐름 |
|---|---|
| 샌드위치 | 탁자 → 탁자 → 탁자 → 탁자 → 도마(자르기) → 탁자(담기) |
| 주스 | 기기(씻기) → 도마(털기·썰기) → 기기(넣기·갈기·따르기) |
| 팬케이크 | 도마(까기·썰기·달걀·젓기·붓기·뒤집기) → 탁자(담기) |
| 샐러드·화채·요거트볼 | 기기(씻기) → 도마(썰기·담기·뿌리기·섞기) → 탁자(담기) |
| 주먹밥 | 도마(뜨기·뭉치기) → 탁자(담기) |

| 컵케이크 | 도마(달걀·젓기·붓기) → 기기(굽기) → 탁자(크림·토핑·담기) |
| 카나페 | 탁자 전부 |

'주기' 단계는 항상 탁자형이다. 한 요리 안에서 화면 종류가 바뀔 때는 같은 종류끼리 묶이도록 단계 순서를 위 표대로 유지한다.

### 1-4. 손과 도구 규칙

- 손은 항상 화면 아래쪽(아이 쪽)에서 들어온다. 도구의 손잡이는 아래를 향한다.
- 도구의 시작 위치는 무대 안 오른쪽 아래(`right:4%; bottom:4%`)다. `position:fixed`와 뷰포트 좌표(`20vw`, `34vh`)는 쓰지 않는다. 잼 숟가락·소스 숟가락·뜨기 숟가락이 해당.
- `gripHand()`, `holdHand()`, `knifeHand()`의 크기 인자를 제거하고 `--sz-hand`만 쓴다. 각도·반전 인자는 유지.

### 1-5. 그림 우선 규칙

- 기본 요리의 놀이 화면에서 `IMG` 키가 있는데 이모지를 쓰는 곳을 모두 그림으로 바꾼다: 컵케이크 토핑 뿌리기(`cupBaked`), 카나페 뿌리기(`canapeDone`), 화채 붓기 대상(`hwachaeBowl`), 요거트볼 시리얼(`cereal`).
- 그림이 없는 요소는 `IMG[key]`가 들어오면 자동 교체되는 구조로 만들고, §9 목록에 프롬프트를 적는다.

### 1-6. 글자 3단계와 줄바꿈

## 2. 학생 프로필과 요리사 화면 (8번)

### 저장 구조 (`localStorage`)

```
cookrun_profiles : [{ id, name, photo(dataURL|null), level:'가'|'나'|'다',
                      stamps:{ [dishId]: count }, stars:number, created }]
cookrun_cur      : id
```

### 흐름

- 설정 모달에 '👧 학생' 구역 추가: 이름 입력 + 사진 첨부(`fileToData`, 320px) + 수준 가/나/다 선택 + 삭제. 최대 12명.
- 시작 화면: 프로필이 1명 이상이면 '시작하기' 위에 얼굴 카드 줄이 뜬다("누가 요리할까요?"). 카드를 누르면 `cookrun_cur` 갱신, "오늘의 요리사 ○○!" 음성, 카드에 요리사 모자(CSS: 흰 반원 + 띠, `IMG.chefHat`가 있으면 교체)가 씌워진다.
- 프로필이 없으면 기존처럼 바로 시작한다(기본 수준 '나', 이름 '요리사').
- 네비 바 왼쪽 집 아이콘 옆에 작은 얼굴 + 이름 표시.
- 완성 화면 제목: "○○ 요리사님, ○○를 완성했어요!"

## 3. 수준 설정 가·나·다 (5번)

```
LV() → { k, hint, ghost, choose }
가: k=0.4, hint=true,  ghost=true,  choose=false
나: k=0.7, hint=true,  ghost=true,  choose=false
다: k=1.0, hint=false, ghost=false, choose=true
N(base) = Math.max(2, Math.round(base * LV().k))
```

### 적용 지점

| 빌더 | 기준값 → `N()` |
|---|---|
| 손 씻기, 잼·소스 바르기, 믹서 갈기, 젓기(바퀴) | 10 |
| 과일 씻기 | 8 |
| 흔들기, 뿌리기 | 6 |
| 까기, 뭉치기 | 5 |
| 짜기 | 4 |
| 뒤집기, 뜨기 | 3 |
| 반복 썰기 | 재료별(10, 4) |
| 문지르기(px 거리), 붓기·굽기(시간) | 거리·시간에 k 곱함 |

- `hint=false`: `.bubblehint`, `.povhint`, `.hintglow`를 숨김. 음성 안내는 유지.
- `ghost=true`: 단계 시작 후 8초 동안 `pointerdown`이 없으면 반투명 손이 제스처를 시범한다. 각 빌더가 `ghost(w, type)`을 호출해 종류를 등록한다. `type` ∈ `lr`(좌우), `circle`, `down`, `up`, `tap`, `drag(from,to)`. CSS 키프레임 6종. 입력이 들어오면 즉시 사라지고 타이머 재시작.
- `choose=true`: 두 번째 단계부터 `renderStep()` 앞에 '다음은 무엇일까요?' 화면을 끼운다. 정답 단계 카드와 같은 요리의 다른 단계 카드 1장을 좌우 무작위로 보여 준다. 틀리면 흔들림 + "아니에요. 순서를 다시 보세요" + 정답 카드 깜빡임 후 재시도. 맞으면 `SND.good` 후 진행.

## 4. 효과음 합성 (4번)

`SND`에 아래 소리를 추가한다. 모두 `ac()` 기반. 노이즈는 1초짜리 화이트 노이즈 버퍼를 한 번 만들어 재사용한다.

| 키 | 합성 | 쓰는 곳 |
|---|---|---|
| `sizzle(start/stop)` | 노이즈 → 밴드패스 3kHz → 진폭 4Hz 흔들림 | 뒤집기, 굽기, 오븐 조리 중 |
| `blender(start/stop)` | 톱니파 90→130Hz + 노이즈 소량 | 믹서 단추 누르는 동안 |
| `water(start/stop)` | 노이즈 → 로우패스 1.2kHz + 미세 변조 | 수도꼭지, 씻기, 설거지 |
| `chop()` | 노이즈 20ms + 사인 120Hz 60ms | 썰기, 자르기 |
| `knock()` | 사인 400Hz 30ms + 노이즈 | 달걀 톡톡 |
| `crack()` | 노이즈 80ms 하강 필터 | 달걀 벌리기 |
| `nom()` | 삼각파 300→180Hz 120ms | 먹기 한 입 |
| `stamp()` | 사인 150Hz + 노이즈 50ms | 도감 도장 |
| `twinkle()` | 사인 1500/2000/2500Hz 순차 | 황금 재료, 첫 완성 |
| 기존 `good/pop/cut/clap/squirt/ding` | 유지 | |

- `SFX_FILES = {}` : 키에 data URI를 넣으면 `<audio>`로 그 파일을 재생하고 합성은 건너뛴다.
- 설정 모달 '🔊 소리' 구역을 세 토글로 나눈다: 효과음 / 음성 / 진동. `SET.sfx`, `SET.tts`, `SET.vib`. 기존 음량 단계는 유지.

## 5. 손님 주문과 주기 (1번, 2번)

### 손님 데이터

```
CUSTOMERS 기본 6명: [{id:'c1',nm:'친구',e:'👧'},{id:'c2',nm:'친구',e:'👦'},{id:'c3',nm:'선생님',e:'👩‍🏫'},
                     {id:'c4',nm:'할머니',e:'👵'},{id:'c5',nm:'곰',e:'🐻'},{id:'c6',nm:'토끼',e:'🐰'}]
IMG.cust_c1 … cust_c6 가 있으면 그림으로 교체.
cookrun_customers : [{nm, img}]  (설정에서 사진 손님 추가, 최대 8명)
SET.order : true|false (기본 true)
```

### 주문 흐름 (`SET.order=true`)

1. 시작(요리사 선택 포함) → 새 화면 `s-order`: 왼쪽에 손님(얼굴 `--sz-food`), 말풍선에 주문 요리 그림 + "○○ 주세요!". 음성: "안녕하세요. 저는 ○○를 주문할게요."
2. 주문은 준비된 요리 중 무작위. 현재 학생의 도장이 없는 요리를 2배 가중.
3. '좋아요!' 단추 → 기존 요리 고르기 화면. 상단 안내 상자에 손님 얼굴 + 주문 그림이 붙어 있다. 가·나 수준은 주문 요리 카드가 깜빡인다.
4. 다른 요리를 누르면 흔들림 + "손님은 ○○를 주문했어요." 맞는 요리를 누르면 기존 레시피 확인으로 진행.
5. `currentOrder = {customer, dish}` 를 세션 변수에 둔다.

### 주기 단계 (`buildGive`)

- 모든 요리의 `addServeStep` 뒤에 `addGiveStep`을 붙인다. 레이블 '주기', 문장 "손님에게 드려요".
- 탁자형. 왼쪽에 완성 요리가 담긴 접시(드래그), 오른쪽에 손님 얼굴(`--sz-vessel`) + 접시 놓는 자리(점선).
- 접시를 손님 앞에 놓으면 손님 얼굴이 😋(또는 `IMG.cust_xx_happy`)로 바뀌고 "냠냠 먹어요. 세 번 눌러요" 말풍선.
- 음식을 탭할 때마다(3회, `N(3)`): 음식이 손님 입 쪽으로 살짝 이동 후 33%씩 축소, `SND.nom`, 부스러기 반짝. 3회 뒤 빈 접시 + 하트 입자 + "맛있어요! 고마워요!" 음성 → `succeed()`.
- `SET.order=false`일 때: 손님 대신 현재 학생 얼굴(사진 없으면 😋)이 앉고 문장은 "내가 먹어요".

### 순서 복습 카드

'주기' 단계 카드는 🍽️➡️😋 이모지 조합(그림 `IMG.cardGive`가 있으면 교체).

## 6. 요리 도감 (3번)

- 시작 화면에 '📖 도감' 단추. 새 화면 `s-book`.
- 격자: 기본 11종 + 과일 꼬치 + 교사 요리. 도장이 있으면 완성 그림 + 횟수 배지, 없으면 회색 실루엣(`filter:grayscale(1) opacity(.35)`).
- 상단: "○○의 도감 · 요리 N/12 · ⭐ N". 별은 황금 재료로 얻는다.
- `finishCooking()`에서 `addStamp(dishId)`: 완성 화면에 도장이 쾅 찍히는 애니메이션(`scale 3→1`, 회전 -12°, `SND.stamp`). 첫 완성이면 금색 테두리 + `SND.twinkle` + "처음 만든 요리예요!".
- 12종을 모두 모으면 도감 화면 진입 시 한 번 축하 화면(색종이 + "요리 박사!" + 왕관 CSS). 플래그 `profile.master=true`.
- 프로필이 없을 때는 '손님' 익명 프로필을 자동 생성해 기록한다(이름 '요리사').

## 7. 선택이 결과에 반영 (7번)

공용 빌더 `buildChoice(w, {title, say, options:[{id, label, html}]}, onPick)`: 카드 2~3장, 누르면 `PICK[key]=id`, `SND.pop`, 300ms 뒤 `succeed()`. 수준과 무관하게 항상 카드는 2~3장.

| 샌드위치 | 자르기 앞 '모양 고르기': 세모 / 네모 | 점선이 대각선/세로. 자르기 방향 판정은 동일(아래로). 완성: 세모=`heroCut`, 네모=`hero` 세로 반 분할 합성 |

## 9. 새 조작 활동 4가지

### 9-1. 달걀 깨기 `buildCrackEgg(w)`

- 도마형. 가운데 반죽 그릇(`pcRaw`), 오른쪽 위에 달걀(`egg`, `--sz-food`×0.6) + 잡는 손.
- 1단계: 달걀을 탭할 때마다(`N(3)`) 달걀이 그릇 가장자리로 내려갔다 올라오며 `SND.knock`, 금 그림(CSS 지그재그 선)이 한 줄씩 늘어남.
- 2단계: 달걀을 아래로 70px 끌면 `SND.crack`, 달걀 그림이 위·아래 반으로 갈라지며(clip-path 두 장) 노른자(CSS 노란 원 + 흰자 타원)가 그릇으로 떨어짐(`land` 애니메이션). → `succeed()`.
- 팬케이크 '반죽 젓기' 앞, 컵케이크 '반죽 젓기' 앞에 삽입. 편집기 `CUSTOM_ACTS.crack` 추가(문장 규칙 `/달걀|깨/`).

### 9-2. 수도꼭지 돌리기

- 기기형 부분 동작. `jFaucet` 그림 위에 손잡이 원(CSS, `--sz-hand`) 배치. 손잡이를 중심으로 원 드래그 누적 각도 ≥ 1바퀴(수준과 무관하게 1바퀴 고정)면 물줄기 + `SND.water.start`.
- 적용: ① 손 씻기 화면(`goPrep`) — 세면대 위 수도꼭지 손잡이를 먼저 돌려야 문지르기 시작. ② `buildWashFruit` 0단계. ③ 설거지 0단계.
- 돌리는 동안 손잡이와 손이 함께 회전. 입력이 끊기면 그 자리에서 멈춤(되감기 없음).

### 9-3. 설거지 `buildDishwash(w)` (요리 뒤 손 씻기 대체)

- 기기형. 세면대(`basin`) 위 접시(`plate`)에 얼룩(CSS 반투명 갈색 점 4개). 수도꼭지 돌리기 → 수세미(CSS 노란 사각 + 초록 윗면, `IMG.sponge` 자리)를 잡고 좌우 문지르기(`N(10)`): 거품 올라오고 얼룩이 한 개씩 사라짐 → 마지막에 물줄기 아래 헹굼 반짝 → "접시가 깨끗해요!" → `finishCooking()`.
- `goPrep("after")`가 이 빌더를 호출한다. 요리 전 손 씻기는 유지.

### 9-4. 과일 꼬치 (새 요리 `skewer`)

- `DISHES`에 추가: `{id:"skewer", nm:"과일 꼬치", e:"🍢", freeChoice:true, need:JUICE_FRUITS}`. 자유 선택 과일 2~3종(2종 미만이면 "두 가지 이상 골라요").
- 단계: 씻기 → 썰기(`buildCutBoard`) → 꽂기(`buildSkewer`) → 담기 → 주기.
- `buildSkewer`: 도마형. 위쪽에 '본보기' 꼬치: 고른 과일로 만든 ABAB(2종) 또는 ABCABC(3종) 패턴, 길이는 수준별 고정(가 4, 나 4, 다 6). 가운데 빈 막대(CSS 갈색 긴 막대 + 뾰족한 끝) 위에 점선 자리. 아래 쟁반에 썬 과일(`_s` 그림)이 종류별로 쌓여 있음. 자리에 맞는 과일을 끌어다 놓으면 `SND.pop` + 꽂힘. 틀린 과일은 튕겨 나가며 "다음은 ○○예요" 음성. 다 채우면 본보기와 나란히 반짝 → `succeed()`.
- 완성 그림: 패턴대로 꽂힌 꼬치를 CSS로 합성. `IMG.skewerDone`가 있으면 교체.
- 편집기 `CUSTOM_ACTS.skewer` 추가(문장 규칙 `/꽂|꼬치/`).

## 11. 검증 방법

1. `tools/walk.mjs`(Playwright): 요리 12종을 모두 골라 네비 '다음'으로 전 단계를 돌며 단계마다 스크린샷 저장. 콘솔 오류 0건, `console.assert` 실패 0건을 확인한다.
2. 같은 스크립트에서 수준 가/다, 주문 모드 on/off, 프로필 있음/없음 조합으로 한 번씩 더 돌린다.
3. 스크린샷에서 손·도구·그릇 크기가 토큰과 일치하는지, 이모지가 기본 요리 화면에 남아 있지 않은지 눈으로 확인한다.
4. 제스처 자체(문지르기·젓기·돌리기)는 Playwright `mouse.move` 시퀀스로 각 빌더를 1회씩 완료시키는 테스트를 둔다.
5. 교사가 실제 태블릿에서 1회 전체 플레이.
